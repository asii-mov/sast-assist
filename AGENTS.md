## Learned Workspace Facts

- The session scratchpad under `/tmp/claude-1000/...` is wiped between sessions; anything that must survive (clones, candidate packages, rubrics, notes) belongs in the repo tree, not the scratchpad.
- `semgrep`, `codeql` and `uv` are installed on PATH at `~/.local/bin` (semgrep 1.177.0, CodeQL 2.26.4); `node` is v22.22 at `/usr/bin/node`. Scanners do not need installing before a run.
- The skill is TypeScript that Node runs directly (Node 22.18 or newer, no build step). The type checker is a dev dependency at the repo root: `npm install` once, then `test/run-all.sh` type-checks. Run `test/run-all.sh` from inside `skills/sast-remediate`; from the repo root its prose check cannot find its script. npm here refuses package versions published in the last 7 days, so pin versions older than that.
- Subagent fan-out repeatedly dies on session rate limits (HTTP 429): one dropout during the design arena, four interrogate reviewers, two more on the implementation fan-out, the sonnet executor for the R3 rescan-config plan, and a prior occurrence recorded in `.work/TODO.md`. Plan multi-agent steps to tolerate dropouts, or do the work serially.
- The skill listing is ~96 skills at ~5,086 est. tokens against a budget of roughly 1% of the context window (~2,000), so entries get truncated out of it. That is why pstack skills invoked by slash command (`/pstack:interrogate`, `/pstack:poteto-mode`, `/pstack:how`) can be absent from the session listing while present on disk under `~/.claude/plugins/cache/cursor-plugins/pstack/<version>/skills/` and `~/Projects/cursor-plugins/claude-marketplace/pstack/skills/`. Check both before concluding a named skill is missing.
- pstack's default model slugs (`grok-4.6-fast-xhigh`, `gpt-5.6-sol-max`, `claude-fable-5-1-thinking-max`) do not resolve here, and there is no `~/.claude/rules/pstack-models.md` override. Available Agent models are opus, sonnet, haiku and fable, but the user has said never to use fable; use opus (Opus 5.5) wherever fable would go.
- The pipeline is run from `skills/sast-remediate` as `node bin/run.ts --target=<repo> --scans=<dir> --out=<dir>` (optional `--scanners=semgrep`, `--semgrep-config=<pack>`, `--codeql-suite=<suite>`, `--model=opus`, `--provider=anthropic|openrouter`). `--provider=openrouter` needs `OPENROUTER_API_KEY` set, still drives the Claude Code CLI (pointed at OpenRouter), and `--model` then takes OpenRouter model names such as `openai/gpt-5`. Scans and rescans default to `p/default` and `security-extended` (`DEFAULT_SCAN_CONFIG` in `bin/scan.ts`). The saved scans in `.work/targets/scans-mkcert` were made by hand with `--config p/trailofbits`, run from inside the target's root, so reusing them needs `--semgrep-config=p/trailofbits`. Agents run with `--restricted`, which ignores user settings, so pass `--model` or they use the CLI's built-in default.
- Live targets and run outputs live under `.work/targets/` (e.g. `mkcert`, `vuln-app-git`). The project root became a git repo on `main` on 2026-09-22, with `.work/`, `node_modules/` and `.claude/hooks/state/` gitignored. Since 2026-09-23 it has a GitHub remote, the private repo `asii-mov/code-scanning`, and `main` tracks `origin/main`. `fixtures/vuln-app` has no git repo of its own, so the fix stage needs the git-backed copy `.work/targets/vuln-app-git`. Further `git clone`s of external GitHub repos have been denied by the permission layer, so new live targets may not be obtainable.
- The user has only Claude Code: no Claude Desktop and no claude.ai chat. MCP servers that draw their UI in the chat window (MCP Apps) do not render here, so build diagrams and visual explainers as Artifacts (web pages) instead.
- Live runs against real targets keep surfacing bugs in the joins between components that the 150+ fake-agent tests never catch; treat a live run, not the green suite, as the real check.
